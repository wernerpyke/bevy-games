# Roadmap: completed items

Items moved here from `ROADMAP.md` when they were done. History only: the lasting rules are in the extension docs and the ADRs. Items are not numbered. Newest are at the end.

### Map backgrounds (random fill)

Done 2026-11-08. A map file has an optional `background:` block: a colour, and tile images drawn over it with a chance per cell (`fill`), a shift (`jitter`) and a size (`scale`, any number above 0). The kit parses it and places the images (`map.rs`, `map_background.rs`, `adr-x36`). Long Way draws it from `ground_tiles.aseprite` (`background.rs`, `adr-lw26`). Each cell rolls its own dice from the map name, `seed` and the cell, so the ground is the same on every load. Not seen on screen: fill 0 and fill 1 (covered by unit tests) and the web build in a browser. The repeating pattern mode is open in `rm5`.

### Screen layout, HUD bar and app states

Done 2026-11-07. The window is split into regions with a camera and a UI root each (`screen.rs`, `hud.rs`, `adr-x34`). Long Way has a HUD bar above the game: 576 by 180 on screen, 160 art pixels high, 31.25% of the game view, in a 576 by 756 window (`adr-lw24`), with one text label in Courier Prime. A `GameCamera` marker replaced `Camera2d` in every kit query, because a second camera silently stops a `Single` system. UI is written in art pixels through `UiScale`. The kit has the app states `Loading`, `Title`, `Playing` and `GameOver`, and pause as a sub state (`app_state.rs`, `adr-x35`): the layout follows the state, pause stops virtual time, dims the game and the HUD and opens an empty dialog slot, and `--skip-title` (always on for scripted runs) skips the title once. Learnings: the first camera on a window clears all of it, so the HUD camera has no clear and its background is a UI node; a UI root with no target goes to the camera marked `IsDefaultUiCamera`, which keeps the info box and the map fade in the game region; macOS shrinks a window that is taller than the screen, so a 720 by 945 window gave a wider view, and the window had to fit (`rm10`); the script clock now uses real time so scripts run while paused. Rules: `dev-docs/extensions/screen-layout.md`. Open: `rm12` (content for the screens, the overlay mode) and `rm10` (adapting to the screen).

### Moving between maps

Done 2026-11-06 (`dev-docs/extensions/map-transitions.md`, `adr-x30` to `adr-x32`). Maps have exits and entries in their front matter. The kit checks the links between maps, runs a scene transition (fade) and a seamless transition (the next map joins the world and the player crosses a doorway), places the player at the same position along the entry strip, and eases the camera limits. The F3 grid has one grid per active map. Long Way has three maps joined by one seamless and two scene transitions. Known issues: no exit back from the second map, enemies and projectiles across a seam are not handled, `CameraBounds` is an eased box in a seamless game, and what a map keeps when the player returns (destroyed objects) is not decided (`dev-docs/extensions/map-transitions.md`, "Returning to a previous map"). The eased box means R-Town style systems that read `CameraBounds` as the map area do not fit seamless maps yet.

### Reusable dev-scripts for screenshots and art checks

Done 2026-11-05. `dev-scripts/shot.sh <game> <name> "<commands>" cx= cy= w= h= scale=` runs a scripted run with `--debug`, takes the screenshot and saves a zoomed crop in world units (`target/screenshots/<name>_crop.png`). `dev-scripts/aseprite.sh <script> <file> key=value ...` runs one of four Lua scripts in `dev-scripts/aseprite/`: `crop` (screen or world region, nearest scale), `frame_grid` (a tag or frame range as one scaled grid PNG), `check` (canvas, colour mode, layers, tags with frames and durations, palette check against `game.aseprite`, bounds and feet row per frame, frames cut off at the edge) and `sheet_analysis` (per frame bounds and colours of a pack sheet). The crop is done in Lua and not in `script.rs`, so the kit has no new dependency. Known issues: the crop is centred on world coordinates you give, not on the player automatically; `shot.sh` reads `VIEW_HEIGHT` from `games/<game>/src/camera.rs` with a regex; `lib.lua` (art pipeline rule 1) is still not written, so the scripts stay standalone. Usage: `dev-docs/extensions/dev-scripts.md`.

### Enemies (R-Town)

Done 2026-11-04. A skeleton (random patrol within 120 px) and a goblin (pursues the player) spawn from legend entries of `test.txt` (`every=` and `strategy=` parameters), walk around trees and water with grid path finding, die when a projectile hits them, and kill the player on a touch. F1 resets the whole game state. The kit has the nav grid, goal movement, strategies, spawners, hit boxes, a seedable random number generator and a movement debug view (`dev-docs/extensions/nav.md`, `enemy-movement.md`, `spawners.md`, `adr-x23` to `adr-x27`, `adr-rt12`, `adr-rt13`). Known issues and follow-ups: the screens were not seen by Claude (the display was black during the scripted runs), no hit points or death screen, enemies may overlap, no check that a spawner stands on free ground, no rule against spawning next to the player, a fixed spawn interval only, and the sprites are one front view each.

### Projectile weapons (R-Town)

Done 2026-11-04. X fires a projectile along the player's facing at twice the walk speed. It disappears at blocked areas and the map edge (`dev-docs/extensions/projectiles.md`, `adr-x21`, `adr-rt11`). The flight, hit message and sprite turning are in `game-kit`. Input went through a game-local `PlayerInput` resource (`adr-x22`, `rm8`). Known issues and follow-ups: no damage or hit effects yet (nothing reads `ProjectileHit`), no cooldown or range, a shot stops up to 5 px before the side of a tree because it uses the player's collision areas.

### Text map files

Done 2026-11-02. A map is one text file with front matter and a drawn grid that shows every cell (`dev-docs/extensions/map-files.md`, `adr-x18`, `adr-lw8`, `adr-rt7`). The parser in `game-kit` reads blanks and `.` as empty, checks row labels, rulers and sizes, supports `origin: bottom-left` and `top-left`, and treats legend markers such as `player_start` as ordinary objects. Long Way (`rocks-test.txt`, 32x18) and R-Town (`test.txt`, 60x60, top-left) load their maps this way. The F3 grid can number rows from the top to match a top-left file. Known issues and follow-ups: no layers and one object per cell (`rm3`), footprint drawings are not checked against the real sizes, and the maps are bundled with `include_str!`, with a reload from disk on native (`rm3`).

### Shared code in the game-kit crate

Done 2026-11-02. A second game, R-Town, needed the code of Long Way, so the shared crate `crates/game-kit` was created (`adr-w6`, `adr-x12`). It holds the collision engine with merged outlines and sliding (`Blocker`, `SlideTuning`, `adr-x16`), the depth sort and default layers (`adr-x14`), the markdown map parser with string kinds (`adr-x13`), the pixel camera with a follow system (`adr-x17`), the debug grid, info box and collision overlay, and the scripted run tool (`adr-x15`). Games pass their values through plugin fields and the `Controlled` marker, with no generics. Long Way keeps `Trunk`, the player constants, its kinds and its art. The tests moved with the code, and the kit builds and tests on its own. Learnings: build and test the kit alone, because a workspace build unifies Bevy features and hid a missing `ui_api` feature. Debug sizes must scale with the cell size. Known issues and follow-ups: the scripted run tool has no way to register game specific commands yet (`adr-x15`), the kit has no camera shake or smoothing, and the scrolling debug grid was checked in R-Town only.

### Tune sliding by playing

Done 2026-11-02. The developer played with rocks and trees and accepted the slide rules as they are (`adr-x10`). The values stay: `SLIDE_RANGE_CAP` 64, `SLIDE_RANGE_FRACTION` 0.35, `SLIDE_CLEARANCE` 192, `SLIDE_DELAY` 0.2 s and `SLIDE_SPEED` 120. Options not built: a 96 px cap, or the nearest outline corner with a cap. Known issue: `SLIDE_CLEARANCE` assumes a 64 pixel cell, so write it in cells if the cell size changes. Not checked: a slide past a corner of the lower left patches, a tree touching a rock, and a flicker check of overlapping rocks over several frames.

### Rock clusters, trees and markdown maps

Done 2026-11-01. A markdown map file (replaced on 2026-11-02 by a text grid, `adr-x18`; `dev-docs/extensions/map-files.md` and `games/long-way/docs/maps.md`, `adr-lw8`, `adr-x11`) places rocks and trees. Blocked areas of trunks and rocks merge into clusters with one outline (`outline.rs`), and the player walks around the outline, sliding past edges and into notches (`adr-x10`). Draw order uses layers (`adr-x9`). The debug grid and collision overlay (F3) are sprites on the debug layers. A spec-first review of the collision code found and fixed several problems (the merge of trunks and rocks, corner-touching shapes, slide targets inside shapes). Research and geometry are in `dev-docs/extensions/collision-research.md`, the rules in `dev-docs/extensions/collision.md`, the values in `games/long-way/docs/collision.md`. Known issues and follow-ups: the player clamp to the view can move the player's feet into a shape, the player placed inside a shape can walk freely, `outline` builds one grid over all rectangles so large maps need chunking (`rm3`), and the maps are bundled with `include_str!`, with a reload from disk on native (`rm3`).

### Trees in Long Way

Done 2026-10-31. `Green tree.aseprite` and `Red tree.aseprite` are copied from the legacy library and drawn near the player, each playing all 8 frames in a loop (`games/long-way/src/trees.rs`). Both carry a `Tree` marker component for the coming collision work. ### Tree collision

Done 2026-10-31. The player cannot overlap a trunk from the left or right, can overlap it by 50% of its height when walking up from below, and can walk behind the tree from above but not into its bottom 10%. Draw order follows the feet so it passes behind and in front correctly. The rules are in `games/long-way/src/collision.rs` with 8 unit tests that pass. The blocked areas were first shown with F1 (now the F3 overlay). See `games/long-way/docs/adr.md`. Not tested by hand: the real feel at the screen edge, whether the debug gizmos draw on top of sprites, and the trunk edges (taken from art pixels) and the player's body width (20 each side, an estimate) on screen. Since then: the 50% overlap from below was replaced by a stop at the base line (2026-11-02, `adr-lw1`) and the half width is 14 (`adr-lw15`).

### Forgiving collision (`allow_sliding`)

Done 2026-10-31. `CollisionPlugin { allow_sliding }` is set to `true` for Long Way. Walking straight into a trunk stops the player. After 0.2 seconds of pushing (first 0.5, shortened after the developer tried it), if it is near an edge of the face (within 35% of its length), it slides past it and carries on. The middle of a face never slides it. With the flag off, any blocked move stops it completely. Fixed 2026-10-31 after the developer found it did not work: the push timer reset every few frames because directions were compared as floats (`adr-x5`). Verified in the real game with scripted input: from feet x = 225 the player stops at the trunk, slides left after the delay and walks on; from x = 240 (too far from an edge) it stays stopped. 16 unit tests pass. Tuning constants (`SLIDE_DELAY`, `SLIDE_SPEED`, `SLIDE_RANGE_FRACTION`) were guesses at the time and were tuned by playing later (see "Tune sliding by playing"). See `adr-x4`.

### Visual debug tools and screenshots

Done 2026-11-01. `debug.rs` (now in `crates/game-kit`) has a red grid (F3) with one line per 64 pixel cell, numbered along the top and left edges, drawn below the sprites, with a configurable origin (bottom left for Long Way). It also has an info box (F2) that any system can add values to, starting with the player's position. The scripted input tool has a `screenshot:<name>` command that saves the window to `target/screenshots/` so Claude can check the result. See `adr-x6` and `adr-x5`. Known issues: the corner label overlap (fixed later, see "Debug grid: overlapping corner labels"). With a bottom left origin the grid x numbers shifted against the world when the window was resized, because the view width follows the window aspect ratio. Fixed for Long Way: cell (0, 0) is a fixed world position (`adr-lw8`). Screenshot is native only.

### Ghost enemy and player HP (Long Way)

Done 2026-11-09 (`games/long-way/docs/adr.md` adr-lw28 and adr-lw29, `adr-x40`, `adr-x41`). The `spawn_ghost` legend entry (`!`) puts a ghost in a map when it loads, once, with no saved state. The ghost patrols near its home (`Sentry`), pursues for good when it sees the player (clear line, inside `sight`), is slow (0.3 times the player's speed) and is drawn at 60% of the art. When it touches the player it plays `Attack`, the player loses 1 HP and plays `Hurt`, and the ghost plays `Die` and is removed. The player has 3 HP, shown as a row of heart icons in the HUD. At 0 HP the player stays alive (no game over screen yet, `rm12`). The kit gained the `Sentry` strategy and sight rule, `Strategy` parsing from a legend entry, `touch.rs` and facing tags; R-Town uses them too. Known issues and follow-ups: ghosts cannot be killed yet, the hit lands when `Attack` ends (revisit with several enemies), sight is not seen blocked by a rock or tree in the real game (kit tests only), the web build was compiled but not run, and R-Town enemies were not seen after the refactor (tests only).

### Click to move (Long Way)

Done 2026-11-09 (`adr-x42`, `adr-x43`, `adr-lw30`). The Long Way player walks to the place you click with the left mouse button and goes around blocked cells. A click on a blocked or outside place goes to the nearest place the player can reach. One click sets one goal (no hold-to-follow) and the arrow keys no longer move the player. The kit gained `pointer.rs` (`WorldClick`), the `click:` script command, `Mover::feet_offset`, `NavGrid::nearest_reachable` and `NavInset`. The nav corner bug is fixed: a path leg that starts exactly on a convex box corner and heads into the box is now blocked. Checked in the real game with scripted clicks (open ground, around the tree cluster, a tree cell, the four map edges, a click during a map change, walking while a ghost hits). Known issues and follow-ups: a real mouse click was not tried (the window to world conversion and the HUD bar rejection are checked only by unit tests of the rule), the hurt animation while walking was not seen on screen, touch taps on the web are not handled, the web build was compiled but not run, ghosts now use a nav grid that is 14 px narrower on the sides and 50 px shorter at the top (they never patrol there in the current maps), and seamless joins are still not supported by nav.

### Weapons: fire ring, ice ring, tornado, fireball (Long Way)

Done 2026-11-13 (`PLAN-weapons.md`, in git history). The particle spike's code moved into the kit (`fx`, `fx_strip`, `area`, temporary blocked areas: `adr-x47`, `adr-x48`, `adr-e9`) and Long Way. Enemies have float hit points and die through `Die` (`adr-lw32`). Weapons are cast from the active weapon buttons through `CastWeapon` and hit through `WeaponHit`; every number is in `weapons/values.rs`, and the balance rules b1 to b14 in `balance.md` are enforced by tests where they can be. Each weapon was designed from the user's intent, play tested and tuned: the fire ring kills a ghost with its first tick (`adr-lw33`); the ice ring is a shield that stops at features and stuns a pinned enemy (`adr-lw35`, kit `Stunned` and `ray_distance`, `adr-x46`); the tornado is a mobile shield with a growing push edge and bumps (`adr-lw36`); the fireball is aimed by the game, steers to its target and explodes with a blast (`adr-lw37`). Learnings: particles in flight do not follow a moving emitter, so the tornado's push edge is drawn with sprites placed each frame; a particle sheet made from a growing tag starts each particle as a dot, so the fireball trail uses one full-size frame (`tail`); the weapons run after the kit moves the enemies (`WeaponSystems::Effect` after `FollowSet`), so a barrier can undo a step in the same frame. Not measured: frame time for the ice ring, tornado and fireball, and anything on the web (`PLAN-walls.md` checks all weapons). The fire wall and ice wall: `PLAN-walls.md`.

### Evaluate avian2d (closed without a spike)

Closed 2026-11-14 by the user's decision (`adr-e10`). The item was to spike `avian2d` (and `bevy_rapier2d`) against the custom collision. The custom collision has since grown a nav grid, groups, temporary blocked areas and sliding, all tested without a running world, and its rules are game rules rather than physics, so a physics crate is not wanted.
